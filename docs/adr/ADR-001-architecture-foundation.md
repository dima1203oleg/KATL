# ADR-001: Production Architecture Foundation & Backend Separation

## Status
Accepted

## Context
Платформа KATL створена як швидкий React+TypeScript прототип. Для переходу у production-стадію необхідно позбутися клієнтського захардкодженого стану (`currentPage`, мокових масивів), створити захищений серверний шар, базу даних PIM, підтримку реальних URL-адрес та серверний AI Gateway.

## Decision
1. **Full-Stack Express API + Vite App Router**: Розгортаємо серверний бекенд на `server.ts` з префіксом `/api/v1/*` для PIM, RFQ, синхронізації та AI.
2. **HTML5 History API Routing**: Замінюємо стан `useState('home')` на браузерну навігацію з підтримкою реальних шляхів (`/products`, `/products/catl-tener-h`, `/compare?products=...`, `/solutions`, `/admin`).
3. **PIM Database**: Створюємо керований репозиторій продуктів із журналізацією походження даних (provenance) та верифікацією інженером.
4. **AI Gateway**: Закриваємо виклики штучного інтелекту на сервері без передачі секретів у браузерний бандл.
5. **RFQ Database Pipeline**: Запити клієнтів зберігаються у БД з фіксацією дати, джерела, параметрів потужності та статусу обробки.

## Consequences
- Повний збіг із затвердженим дизайном без регресії існуючого UI.
- Можливість ділитися посиланнями на окремі продукти та порівняння.
- Безпека API-ключів та технічна достовірність даних.
